# Loader 的职责

1. 解析 ELF 头,验证合法性
2. 遍历 Program Header,加载 PT_LOAD 段
3. 处理 .bss(filesz < memsz 的部分清零)
4. 设置段权限(R/W/X)
5. 查找 PT_INTERP, 决定静态还是动态链接
6. 动态链接时加载 ld.so
7. 构造用户栈(argc/argv/envp/auxv)
8. 提供入口地址给内核跳转

不包含(这些是 ld.so 在用户态做的):

- 库依赖解析
- 符号重定位
- GOT/PLT 填充

核心原则:
内核 Loader 负责"把 ELF 文件映射到内存 + 构造运行环境(栈/入口)",
动态链接器负责"在用户态完成库加载和符号重定位"。
两者分工明确,内核不做符号解析。

# 大致示意图

```txt
execve("/bin/ls", ["ls"], [])
  │
  ▼
┌─ 内核 ──────────────────────────────────────┐
│ 1. 打开文件,读入 ELF                        │
│ 2. 验证 magic = 0x7F454C46                  │
│ 3. 创建新地址空间(新页表)                   │
│ 4. Loader 遍历 PT_LOAD 段                   │
│    → 分配页 + 映射 + 拷贝 .text/.data/.bss  │
│ 5. 有 PT_INTERP?                            │
│    ├── 是:加载 ld.so,入口 = ld.so 入口      │
│    └── 否:入口 = e_entry                    │
│ 6. 构造用户栈:argc/argv/envp/auxv           │
│ 7. 丢弃旧地址空间,切换 CR3                  │
│ 8. 伪造 trap frame:CS=ring3, RIP=entry      │
│ 9. 设置 TSS.rsp0 = 内核栈顶                  │
│ 10. IRET → 跳到用户态                       │
└─────────────────────────────────────────────┘
  │
  ▼
┌─ 用户态 ───────────────────┐
│ (如果是动态链接)           │
│ ld.so:                     │
│   → 加载 libc.so 等依赖    │
│   → 重定位 GOT/PLT         │
│   → 运行 .init_array       │
│   → 跳到 _start → main()   │
│                            │
│ (如果是静态链接)           │
│ _start → main()            │
└────────────────────────────┘
```
