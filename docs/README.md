# 本次 loader 任务的阅读导航

这组文档服务于何归当前的任务：实现内核 loader，配合进程与内存模块让第一个用户进程跑起来。
更新日期：2026-10-09。

## 依据与优先级

1. 刘闯提供的[《loader流程说明》](loader流程说明.md)是最高设计。
2. [talk.md](talk.md)说明目标和分工：先跑起一个 PIE，PID 1等后续再谈。
3. 施涵格的 `98a6f0cf` 是可复用实现基线。它适配的是此前没有用户态的环境，不能反过来覆盖最高设计。
4. 本地工具链环境参考 `2740fe19`；源码描述均按 `98a6f0cf` 核对，不沿用旧文档的代码现状。

文中“已有”描述基线代码，“本次要求”来自最高设计，“建议”是实施方案，
“待对接”是设计没有展开的接口细节。后续代码变化时应一起更新对应说明。

## 已确定的职责

| 组件                  | 本次职责                                                                                        |
| --------------------- | ----------------------------------------------------------------------------------------------- |
| 内核 loader（何归）   | 校验 ELF、加载 PT_LOAD、清零 BSS、请求段权限、加载 PT_INTERP 解释器、构造用户栈、交付入口与资源 |
| 用户态 ld.so / 运行时 | 依赖解析、符号绑定、重定位、GOT/PLT 填充及用户态初始化；具体组件分工按运行时约定                |
| 地址空间 / 内存模块   | 用户虚拟地址管理、页分配与映射、内核访问待装载页、权限与同步、回收                              |
| process / arch / 调度 | 进程与执行上下文、内核栈、地址空间安装、进入用户态、调度与退出                                  |

内核加载 `ld.so` 是加载它的 ELF 段，再由 CPU 在用户态执行它，
不是在内核调用现有 `DynamicLinker`。内核也不替静态 PIE 执行 RELATIVE 重定位；
无解释器程序必须无需运行时重定位，或由其启动代码自行完成。

```text
process 准备新地址空间
  → loader 加载主程序
  → 有 PT_INTERP 时加载解释器
  → loader 构造 argc / argv / envp / auxv 用户栈
  → process / arch 安装地址空间和用户上下文
  → 无解释器：主程序入口
    有解释器：用户态 ld.so → 动态链接 → 主程序入口
```

设计示意中的 CR3、TSS、IRET 属于 x86；AArch64/RISC-V 由自己的架构实现完成等价职责。
采用这套职责分工不代表已经实现完整 Linux 用户 ABI，也不要求首笔改动就完成全部 `execve` 语义。

## 当前差距

基线已有校验、段布局、复制/清零、分阶段回滚、动态链接等大量代码。
但 application 在内核完成动态链接、使用平坦堆存储和自定义启动参数，并创建普通线程执行。
因此，“改成进程模型”仍涉及加载流水线、内存后端、栈式启动 ABI 和运行时产物的调整。

旧版文档中以下判断已移除或修正：BSS 未清零、只支持 RISC-V 相对重定位、
把内核重定位当作首期待办、继续沿用自定义启动结构、凭旧编译条件判断测试覆盖范围。
通用知识保留；源码链接改为相对路径，便于从仓库直接阅读。
