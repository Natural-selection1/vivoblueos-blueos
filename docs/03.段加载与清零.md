# 03. 段加载与清零

装载 `PT_LOAD` 的核心语义是：
在目标地址空间准备 `p_memsz` 字节，
把前 `p_filesz` 字节从文件复制进去，
把剩余部分初始化为零。

这与 Rust 中“创建一个已初始化的字节缓冲区，再填入文件内容”有相似之处；
区别是目标可能分散在多个物理页，并且拥有特定用户地址和权限。

## 四个字段构成一条完整规则

设 `B` 为 load bias，`U = B + p_vaddr`：

```text
文件输入区间：[p_offset, p_offset + p_filesz)
目标复制区间：[U, U + p_filesz)
目标清零区间：[U + p_filesz, U + p_memsz)
```

前提包括 `p_filesz <= p_memsz`，所有加法不溢出，文件区间确实存在，目标区间合法并已获得内存。

沿用前两篇的示例：

```text
p_offset = 0x1000
p_vaddr  = 0x2000
p_filesz = 0x0600
p_memsz  = 0x0a00
B        = 0x400000
复制：文件 [0x1000, 0x1600) → 用户 [0x402000, 0x402600)
清零：                         用户 [0x402600, 0x402a00)
```

`0x400` 字节的零不需要存在于 ELF 文件中，
这就是 `.bss` 等零初始化数据节省文件空间的原因。

## 这里的清零来自 segment 规则

即使 ELF 文件里找不到名叫 `.bss` 的 section，
只要某个 `PT_LOAD` 的 `p_memsz > p_filesz`，
该差额对应的运行时字节就必须是零。

实际运行时可读取的内容由这些规则决定，不能靠 section 名称猜测。
反过来，也不要把文件末尾之后的其他内容错误地复制过去凑够 `p_memsz`。

特殊情况也有明确含义：

- `p_filesz == p_memsz`：该段没有这类零填充尾部。
- `p_filesz == 0 && p_memsz > 0`：纯零初始化段，不读取文件内容。
- `p_memsz == 0`：不创建有效内存区间；避免计算 `end - 1`。
- `p_filesz > p_memsz`：文件语义无效，应拒绝。

## 为什么分配内存不代表已经清零

Rust 中 `vec![0u8; n]` 会初始化字节，
`alloc::alloc::alloc` 则不提供零初始化保证。

物理页分配器也可能返回被其他用途使用过的页。
即使 QEMU 刚启动时许多内存碰巧是零，也不能依赖这一点。

如果 loader 漏掉清零，会产生两类问题：
程序读到本应为零的静态变量却得到旧值，以及新进程读到其他用途遗留的数据。
后者说明清零也是隔离语义的一部分。

## 为什么通常先准备整页，再复制所有段

内存模块一般按页分配。假设页大小是 `0x1000`，
示例中的目标区间会占用 `[0x402000, 0x403000)` 这一页。

一个可理解的 eager loading（启动前立即装载）方案是：

1. 先验证所有段，规划需要的目标页及内容区间。
2. 为新映像分配页面，每个新页初始化一次。
3. 把每个段的文件内容复制到对应目标区间。
4. 确保每个段的零填充区间满足要求。
5. 设置进入用户态前的段权限并完成代码可见性同步；重定位由用户态负责。

第 4 步不一定需要再次执行清零：
如果新页已统一清零，且没有后续写入覆盖这些区域，要求已经满足。

不能每遇到一个段就把涉及的整页重新清零。
两个段可能占用同一页的不同字节；后处理的段会抹掉先前复制的内容。
遇到真正的字节范围重叠，应按支持策略验证或拒绝，不能靠遍历顺序决定结果。

## 给内存模块什么样的请求

从 loader 视角，最好能表达:
“往这个进程的用户地址区间写入这些字节”和“把这个区间置零”。
跨页和物理不连续由映射层负责。

教学伪代码如下，函数名不表示当前仓库已有这些 API：

```rust
for segment in validated_load_plan:
    copy_to_user_space(
        segment.user_start, segment.file_bytes
    )
    zero_user_range(
        segment.user_start + segment.filesz,
        segment.memsz - segment.filesz
    )
```

必须先做全局规划，保证上述操作不会破坏其他段，且失败时有回收路径。
真实实现还要处理权限、页边界与资源所有权。

## 对照 `98a6f0cf`

[AllocatedImage::map][ref-1] 已分块读取并写入 `p_filesz` 字节，
随后计算 `p_memsz - p_filesz` 并调用事务的 `zero` 清零尾部。
旧文档“没有显式清零 BSS”的判断已不适用于这份基线。

仍需区分“段尾 BSS 已清零”与“新用户页的所有可见字节都不会泄露旧数据”。
页内段外填充和对齐扩展区域也要由新内存后端或加载规划正确初始化，
不能只因现有 BSS 逻辑正确，就假设用户页全部安全。

[Storage::from_layout][ref-2] 等分配接口的初始化保证仍应按具体实现核对。
本次重点是保留已有复制/清零规则，并使它们在跨页、用户地址不同于内核地址的后端上成立。

## 如何验证

最有价值的清零测试是：
先让目标内存含有非零值，比如 `0xa5`，再加载 ELF，检查文件部分正确、尾部全部为零。
不要只测试刚启动时的“干净”内存。

另外应覆盖纯零段、跨页尾部、零长度段，以及两个段共享页但字节范围不重叠的情况。
你应能在纸上画出每个字节来自文件、来自清零，还是属于段外填充。
